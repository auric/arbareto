# Tasks: Windows Desktop Qualification

**Input**: Design documents from `specs/001-desktop-qualification/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/operations.md, quickstart.md, and checklists/ (all items pass).

**Tests**: The spec (FR-028, SC-002 to SC-004) and the user request require tests. Contract tests come before the code that they test. Fixture tests in real disposable Git repositories come before any staging or commit code. No test passes by default.

**Organization**: Phases follow six batches: (1) shared scaffold and shell boot, (2) repository reads, (3) diff and staging correctness, (4) UI integration, (5) Windows qualification, (6) shell selection. Story phases carry `[USn]` labels. Setup, Foundational, and the cross-cutting qualification phases carry no label.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: The task touches different files from the other `[P]` tasks in its group and depends on no incomplete task. A `[P]` group starts after all tasks above it finish. A sub-heading starts a new group.
- **Exception**: Batch 4 work may start after T090, before batch 3 ends. This covers the tests T118 to T122, T178, and T184 to T187. It also covers the frame tasks T123 to T128, view group A (T129 to T141), and T142 to T144. Each such task still waits for every task that it names in "Depends on".
- **[Story]**: The user story from spec.md (US1 to US5).
- Each task names exact file paths.

## Test harness rules

These rules apply to every test task.

- Every test file calls `printOrigin` from `tests/origin.ts` for each `src/` module that it imports. A green run counts only when its `ORIGIN` lines point into the checkout under test.
- Each batch verification task names one control mutation. The mutation must turn the same command red. Undo the mutation, then rerun green.
- Git tests find Git at test time through `tests/git/git-binary.ts` and skip when Git is absent. A batch verification fails when a test skips for an absent Git.
- Some tests need a condition that the host cannot create, such as another account or a full volume. Such a test skips and names the missing capability. Record that case as `unverified` in research.md.
- Fixtures live only under the owned root from `tests/git/fixture-root.ts`. Tests never touch a developer repository or the user's Git configuration.
- No task commits an executable. Rust process tests re-execute the test binary. Tests find built or installed binaries at test time.
- Mutation assertions use `tests/git/git-oracle.ts`, not only the service parser. They compare full logical index entries, raw index digests, the SHA-256 of every fixture working file, refs, and operation markers.
- A task that says "Report for research.md" does not edit research.md. Its test prints each record as one `OBSERVATION <task ID>: <fact>` line. A non-test task lists the record in its task report. The batch verification task copies these records into research.md. So parallel tasks never edit research.md together.

These rules apply to every task that creates a source file.

- Every new `.ts`, `.tsx`, `.rs`, and `.css` file under `src/`, `src-tauri/src/`, and `tests/` starts with two comment lines. They are `SPDX-License-Identifier: AGPL-3.0-or-later` and `Copyright (c) 2026 Ihor Lifanov` (NOTICE.md section 7(b)).
- JSON files have no comment syntax, so they carry no header.
- Generated or adapted shadcn files under `src/frontend/components/ui/` keep the shadcn MIT notice (research.md R9 "Frontend licence obligations").
- `src/frontend/index.css` gets the header in T124, because T123 needs the plain T005 import.
- Each batch verification task (T065, T090, T117, T149, T171, and T177) runs `rg -F --files-without-match "SPDX-License-Identifier: AGPL-3.0-or-later" src src-tauri/src tests -g "*.{ts,tsx,rs,css}" -g "!**/components/ui/**"`. It runs the same command with `Copyright (c) 2026 Ihor Lifanov`. Each command must print nothing. Before T124, T065, T090, and T117 add `-g "!**/index.css"`.

These rules apply to every task that changes a manifest or a lockfile, or builds a package.

- After T003 and T006, every dependency change needs a record in research.md R10 "Dependency reviews". A dependency change adds or removes a dependency, or changes its version, in `package.json` or `src-tauri/Cargo.toml`. A change to `bun.lock` or `src-tauri/Cargo.lock` is also a dependency change. A script-only `package.json` edit needs no record. The record follows plan.md "Tool and runtime boundaries".
- Each batch verification lists the manifest and lockfile changes since the previous batch verification with `git log --name-only`. It fails when a change has no record.
- Every task that builds a package records the tool versions that ran in research.md R10. Run `rustc --version`, `cargo --version`, `cargo tauri --version`, and `bun --version`. Take the MSVC toolset and Windows SDK from the T001 link probe. Run `& "$env:LOCALAPPDATA\tauri\NSIS\makensis.exe" /VERSION` after the build. Each version must be at least its plan.md minimum.
