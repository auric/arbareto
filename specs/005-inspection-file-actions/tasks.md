# Tasks: History Inspection and Commit View File Actions

**Input**: Design documents from `specs/005-inspection-file-actions/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/operations.md, quickstart.md, and checklists/requirements.md.

**Tests**: The spec (SC-001 to SC-011) and plan.md "Steps" require tests. Each step writes its tests first (plan.md "Steps (riskiest proof first)"). The fact tests F and N of WP3 to WP5 come first in their phases. A failing-test task comes before each implementation task. No test passes by default.

**Organization**: Phases follow the work packages of plan.md "Work packages, in run order": WP1 (batch 0), WP2, WP3, and WP4 (batch 1), WP5 and WP6 (batch 2), WP7 (batch 3), and WP8 (batch 4). WP0 is plan.md, this file, and `/speckit-analyze`. Story phases carry `[USn]` labels. Phase 1 and Phase 8 carry no label.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: The task touches different files from the other `[P]` tasks in its group and depends on no incomplete task of that group. A sub-heading starts a new group. "Depends on" names the exact order.
- **[Story]**: The user story from spec.md (US1 to US9). A task that serves several stories carries the first story and names the others.
- **WP and agent**: Each task names its plan.md work package. The orchestrator dispatches one WP per agent, with the agent that plan.md "Work packages" names. Each phase heading names that agent.
- **Local tags**: `Local: Rust` needs the local Rust toolchain. `Local: Windows` needs the Windows reference host. `Local: package` needs the packaged Windows build. `Local: WSL` needs the `Ubuntu-26.04` distro with Git 2.55. Cloud sessions do not run these tasks (CLAUDE.md "Tool boundaries"). A skip never counts as a pass.
- **Earlier specs**: The 001 to 004 texts stay unchanged in their own specs (spec.md "Changes to earlier requirements"). Tasks implement the changes and cite the changed requirement. No task edits `specs/001-desktop-qualification/` to `specs/004-workbench-ux/`.
- **Portability**: Shared TypeScript code and the generic test harness hold no Win32 FFI. Windows-only behavior stays in `src-tauri/src/` and `tests/windows/` (CLAUDE.md "Project constraints").

## Path Conventions

- Paths follow plan.md "Project Structure": `src/contracts/`, `src/git-service/`, `src/frontend/`, `src-tauri/src/`, `tests/contracts/`, `tests/git/`, `tests/vectors/`, `tests/windows/`, and `tests/wsl/`.

## Harness and tick rules

- The 001 "Test harness rules" stay in force (`specs/001-desktop-qualification/tasks.md`). They cover `printOrigin`, the control mutation, Git discovery through `tests/git/git-binary.ts`, capability skips, `tests/groups.json`, `OBSERVATION` lines, owned fixture roots, and the source headers.
- Every test uses an owned `GIT_CONFIG_GLOBAL` and `GIT_CONFIG_NOSYSTEM=1`. No test touches the user's own configuration (quickstart.md "Prerequisites").
- Oracles are Git's own commands on a copy (plan.md D18). History: `diff-tree` sets and patches. Blame: `git blame --porcelain` with the same options, line by line. Preview: the change of `ls-files -o -i --exclude-standard -z` and `ls-files -c -i --exclude-standard -z` after a real save on a copy. Delete: absent paths, unchanged other bytes, the `.git/index` SHA-256, and the Recycle Bin item.
- Each Recycle Bin test purges every item that it moved, through the reply `recycledPath`. It changes no other Recycle Bin item (spec SC-003).
- Canaries: a command-valued `core.fsmonitor` writes a marker file. The marker stays absent for blame, the folder reveal, and the branch card in an untrusted repository, and for the gated reads before approval (plan.md D18).
- A fact test (P0.2, P0.3) has no implementation of its own. A failed fact is a finding, not a red task. The test prints `OBSERVATION <task ID>: <fact>` with the observed Git or Windows version. The batch verification copies it into research.md R17. A failed fact changes contracts/operations.md and plan.md before the dependent implementation task starts, and the change runs `/speckit-analyze`.
- Each new test file in `tests/contracts`, `tests/git`, or `tests/wsl` adds its line to `tests/groups.json` in the same task: `parallel`, or `serial` with its reason. A timing test or a 100,000-path test goes into `serial`. `tests/windows` files are not in `tests/groups.json`.
- App runs set `ARBARETO_PROFILE_ROOT` to a scratch folder.
- A task is ticked only after a green full run (`bun run test:all`) on Windows that verifies it, with `ORIGIN` lines in the checkout under test. A `tests/windows` task is ticked only after a green `bun run test:windows` on the reference host.
- Batch verification tasks use only the README "Development" commands.
- No heuristics: every outcome comes from a documented Git exit code, machine-readable Git output, a fresh read, an OS fact, or a contract value (spec FR-001, SC-011). A test that asserts a refusal asserts its code and reason, never Git's message text.
